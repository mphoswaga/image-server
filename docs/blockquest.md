# BlockQuest

Open My games → Choose a game → BlockQuest on an existing multiple-choice question set. Choose Smartboard for two teams, or Single-player mission for teacher practice. Test smartboard · two teams and Test single-player open isolated practice runs with fictional learners and no marks saved. A Test smartboard link is also available on the game setup screen. Test runs never replace an ongoing class game. Learners find BlockQuest in the existing Play menu after joining their assigned question set.

On desktop smartboards, tall playfields sit on the left and right. The question and controls occupy the bottom centre, expanding upward for longer prompts and choices without overlapping either playfield. Smaller screens retain the stacked layout.

Smartboard shuffles the selected roster into two teams, alternates team turns and cycles through every member of a team before reshuffling. Without a roster, it uses anonymous players and does not record learner marks. Single-player learner sessions are private to the game and authenticated learner; teacher single-player previews do not save learner marks.

New games start a 20-second countdown as soon as the learner name and question appear. The question alone is read automatically using the existing natural Marin narration service; choices are never narrated automatically. A missed deadline records an incorrect answer. Incorrect answers show the answer and explanation for 2.5 seconds, then automatically call the next learner. A correct answer earns 100 points and immediately unlocks three distinct shapes for a 15-second building turn. Choose, rotate and move a block using touch or keyboard (left/right, up to rotate, Enter to place). An unearned translucent block descends during the answer countdown. After a correct answer the selected block falls from the top, one row per 1.5 seconds; shape changes and steering must fit at its current height. The ghost previews its landing. Drop block places it immediately; collision or the building deadline also places it automatically. Placed blocks earn 10 game points and each full row earns 100. Clearing multiple rows adds 50 points for each pair of rows cleared together (two rows: 260 total; three: 460; four: 710). Matching smartboard team turns receive the same three-shape offer, saved across reloads and tied to turn number even if a team answers incorrectly. A normal placement takes one second; row clears take 3.4 seconds for a neon charge, shattering blocks, particles, settling, a points burst and rocket construction before the next turn opens automatically. Teacher pause freezes answer, falling and scene clocks. Incorrect answers reveal the correct answer and explanation without awarding a block. Music reuses the bundled ColonyQuest soundtrack, with local building, success, row-clear and countdown effects. The neon arena uses cyan and pink team borders and illuminated blocks. A Web Audio analyser measures only the playing soundtrack to drive a smoothed ambient glow at up to 20 updates per second. Glow stops for muted music, paused or ended games, hidden tabs and reduced-motion preferences; narration and effects do not drive it. Voice, music and effects have separate controls. Browser audio requires the initial Start/Resume interaction. The highest combined answer and building score wins. Existing saved games retain their original manual pacing; start a new game to use timers. If none of the offered shapes can fit, a rescue clears the bottom three rows without awarding points. Each team builds a rocket in three earned stages: boosters, cabin and nose. The third row completes a short launch. Rescue removals never advance this mission. Solo ends on three cleared rows or the last question; smartboard ends on the last question or teacher Finish. Teacher pause and refresh resume are supported. Returning teachers can also choose Restart game beside Resume saved game. Confirmation replaces the unfinished run with a fresh question-one game and empty towers; previously completed results remain unchanged. Learners cannot restart an unfinished run.

Sessions and original question snapshots are persisted under DATA_DIR/blockquest. The server validates identity, phase, revision, answer choice and placement. Answer keys are not sent ahead of feedback. Earned game points are separate from correct/attempted learning results. Named learner evidence uses original question indices and idempotent run/student result IDs. Completion integrates with the existing game results and gradebook pipeline.

Validation: node --test tests/blockquest*.test.js; npx playwright test tests/e2e/blockquest.spec.js --project=windows-100 --project=mobile. Browser checks cover smartboard and solo flows, replay protection, resume, learner-only control boundaries, private sessions and persisted learning results. Classroom trials and direct smartboard hardware testing are still needed before claiming classroom readiness.
