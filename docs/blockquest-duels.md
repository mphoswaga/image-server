# BlockQuest class duels

My games → Choose a game → BlockQuest → Live duels opens teacher setup. Choose one assigned class, 3- or 5-minute duels, and 1–10 rounds. Random teams, Boys vs Girls, saved class teams and editable assignments are available. Unknown genders remain unassigned for teacher review. Remember teams is optional and does not alter the roster or overwrite a saved team profile unless selected.

Open the learner lobby, share the existing learner game link or room code, and wait for learners to join. The BlockQuest choice in the learner Play menu opens an active teacher-created competition; independent play remains solo when no class competition is active. Only learners selected from the teacher’s assigned class can access the competition.

Start announces all pairs for six seconds, then everyone plays independently. Pairing prioritizes other teams and opponents not previously faced. Remaining learners from the same team can have friendly duels; one odd learner receives a clearly labelled computer opponent. New arrivals wait for the next round. The teacher can pause everyone or finish early. Automatic round boundaries show the previous winners and announce new opponents. The final class leaderboard shows the top ten, with team totals throughout.

Each question allows 20 seconds with a large clock and warning beeps for the last ten. No block preview appears during answering. Correct answers earn 100 points and immediately start a 15-second building turn. A block placement earns 10, full rows 250 each, multiple rows add 150 points per pair of cleared rows, and consecutive clears add a chain bonus capped at 150. Incorrect answers and timeouts show brief feedback and continue automatically. Both duel opponents receive the same shuffled question order and block offers. Banks repeat during a timed round so a quick learner can keep building. Each new round starts fresh towers; accumulated points and duel wins remain on the class leaderboard.

Class competition points include all practice answers and builds. Learning marks use only the first attempt at each original question across the competition; repeated questions cannot inflate these marks. Original question indices feed the existing game results and gradebook pipeline. Completion is idempotent. Computer players never receive learner marks.

Test live duels uses a separate sample class and saved competition, with nine computer players and one sample learner the teacher can play in another tab. Test scores never enter real learner records. Live multiplayer is teacher-created; learners cannot create, start, pause or finish competitions.

The server owns clocks, turns, pairings and scores. Client actions require the current private run and revision. Responses include the learner’s own turn, the opponent’s tower and public class standings; future answer keys, other learners’ responses and internal offer plans are excluded. State is cached in one server process and flushed to DATA_DIR/blockquest-live once per second. After a server restart an active competition restores paused so the teacher can resume with its saved remaining time. Horizontal scaling would require shared match coordination; the current deployment uses one web process.

Validation: node --test tests/blockquest*.test.js; npx playwright test tests/e2e/blockquest-live.spec.js tests/e2e/blockquest.spec.js --project=windows-100 --project=mobile. The live suite covers sample setup and play, independent authenticated learners, role boundaries, idempotent marks, and a 25-learner concurrent join/poll/answer flow. These checks do not replace a classroom trial on learner hardware and school Wi-Fi.

Learner layout: the question and its own answer clock lead the screen. The opponent stays in a small, noninteractive window showing their tower, answered questions and rows. A cyan/pink versus bar shows each learner’s name and current duel points; the leading player occupies a larger share, with 50/50 at a draw and a minimum 5% of the bar retained for each colour. Questions and building progress are private and independent. During the learner’s own build, their tower is large enough to steer a piece beside the building controls. Team totals and the class leaderboard remain in the teacher control room; learners see their class leaderboard at completion.

At a round boundary the previous winner and both duel scores are shown for four seconds, followed by the six-second announcement of the next opponent. The last round also shows its duel result before the class top ten. Results and learning evidence are saved when the competition ends, independently of this presentation. Pausing between rounds preserves both the result and matchup clocks.

Battle rules (new competitions): both players start with the same four-cell gap and I/O/T opening offer. A row clear cancels queued incoming rows first, then sends up to two breakable rows to the opponent. Queued rows plus attack rows already on the board are capped at two. Incoming rows apply only after a correct answer starts the next build, so they cannot move a live piece. Towers occupied in the top three rows automatically block incoming rows. Opponent actions never deduct learning marks or rewrite an answer. Events are server-owned and dispatched once per placement, including automatic drops and computer turns.

The final 30 seconds build the existing soundtrack with a gentle tempo increase and bass pulse, ducked during narration. Music off, pause and hidden tabs stop the build-up. Question beeps remain separate.
